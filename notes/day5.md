# Day5 笔记：把终端程序套成网页

## 今天做了什么

1. 装 Streamlit，把 `main.py` 的逻辑包成 `app.py`，网页上能点按钮生成计划。
2. 加侧边栏输入（目标 / 场地器械 / 今天状态），这些值真正进了 prompt。
3. 用 `st.session_state` 保存结果，改控件时计划不再消失。
4. 用 `try/except/else` 包住模型调用，报错显示红框而不是白屏。

## Streamlit 的心智模型

**每次用户操作，整个脚本从头重跑一遍。**

不是「点了按钮只执行 if 里面」。所以：

- 局部变量每次重跑都会丢 → 要保留的东西放 `st.session_state`
- 顶层代码每次交互都执行 → 调模型这种耗时又花钱的操作必须放在 `if st.button(...)` 里
- 不能用模块级全局变量存用户数据 → Streamlit 是一个进程服务所有访问者，全局变量会在用户之间串数据

## 今天抓到的两个真 bug

**① 器械约束只写在 prompt 里，没有落在 SQL 上**

现象：选「家里（哑铃）」，生成结果里 5 个动作有 3 个是杠铃 / 健身房器械。
原因：`candidates()` 只按 `pattern` 筛库，`equipment` 只作为一句话进了 prompt。
修法：`WHERE equipment IN ('哑铃','自重')`，让候选里根本没有做不了的动作。

结论：**能落到 SQL 的约束，永远不要指望 prompt 遵守。** prompt 是请求，SQL 是强制。

**② 动作库按健身房造的，自重动作覆盖不全**

打数据发现：家里（自重）场景下 push 5 / pull 5 / legs **0**。
原因：原库 69 条，自重只覆盖了胸和背。
修法：补 16 条自重动作（腿 10 / 推 2 / 拉 4），动作库 69 → 85。顺序是先补数据再加过滤，反过来「家里（自重）」会直接空库。

## 三个最想改的地方（下周做）

**① 渐进超负荷没落地（最严重）**

`last_weight()` 写好了，但从未被调用。prompt 里写死「重量填 0」，
所以生成的计划永远是 `weight_kg: 0`。

这个项目对外的第一条卖点就是「记得你上次练了多少」，现在它是空的。
README 里已经标注成「尚未实现」，但这是最该先补的功能。

**② 「写入训练记录」是可选勾选**

默认不勾。忘了勾 → `sessions` 表没数据 → 下次 `decide_pattern()` 判断错，
可能连续两天练同一个部位。默认值选错，用户不会怪自己，只会觉得工具不准。

**③ 生成过程中按钮没禁用**

连点会重复调模型，重复付费。`st.button` 本身不提供「运行中禁用」的能力，
需要用 `st.session_state` 记一个 running 标志，配合 `disabled=` 参数。
